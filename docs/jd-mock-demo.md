# JD 固定演示结果

招聘演示工作台收到明确的 JD 生成请求后，直接运行本地任务，经过 1.5 秒准备状态保存固定 HTML。任务派发、正文准备和完成回复均不调用模型，也不实时读取飞书。飞书应用和浏览器发布能力保留原实现。

## 内容与设计

设计来源：[Figma JD 弹窗 523:2143](https://www.figma.com/design/kZRCbPpo7it0jcJLIgmxXp?node-id=523-2143)。完整保留公司介绍、职责、要求、加分项、待遇、招聘流程和右侧招聘信息。公司名称（包括原稿的 Syntrropic 拼写）、来源卡片、页尾和窗口招聘标签均使用星流科技。右侧品牌图标复用项目已有的 `public/icons/company-careers-logo.svg`，不使用 Syntropic 的 S 标识。

固定岗位为高级 AI Agent 研发工程师，Agent Platform，北京 / 上海，6 人，全职，3–8 年，混合办公。桌面招聘目标、日程、快捷提示、待发布岗位说明和发布表单默认值保持一致。其他岗位的历史种子数据不改写。

## 实现边界

- 仅对 `SYNTROPIC_PRESENTATION_ROOT/workspace` 内的桌面对话生效。普通工作台和其他业务请求继续原有流程。
- `lib/recruiting-jd-fixture.ts` 保存固定文案，`lib/recruiting-jd-demo-renderer.ts` 与 `public/design/jd/result.css` 负责独立 HTML。图片和样式内嵌到文件，打开成果不依赖远端资源。
- `lib/recruiting-jd-demo.ts` 创建 SDK SessionManager 任务记录并保存文件，不创建后台模型执行循环。记录包含显式的 simulated 元数据和零模型用量；“内容依据”是固定演示文案，不代表本轮实时读取飞书。
- `lib/rpc-manager.ts` 在模型请求之前接管生成操作，沿用任务通知、会话历史、运行状态和成果发现。保存使用临时文件、读回检查和原子替换；取消不会覆盖已有成果。重复请求在运行期间被拒绝，完成后可再次生成同样内容。
- 文件继续保存为 `ai-agent-engineer-jd.html`。发布建议仍传递实际文件路径，通过原浏览器流程填表、提交和核对；不会以 mock 声称发布成功。
- 演示模型尚不可用时，招聘桌面对话允许 SDK 正常选择默认模型，以便本地 JD 入口仍可启动。浏览器发布继续需要其原有模型配置。

## 验证

- 类型检查与修改范围 ESLint 通过；JD、成果提取、会话生命周期、桌面提示相关 34 项检查以及招聘服务 11 项检查通过。新增检查覆盖无模型调用、完整正文、公司图标、重复保存、目录限制、取消、任务历史和成果恢复。
- 浏览器验证了真实桌面输入、自动打开 JD、关闭与重开、刷新恢复、最大化/还原和重复生成。热启动两次观察约 2.1 秒打开弹窗，不作为所有机器的耗时保证。
- 补充以真实 Electron 44.2.0 开发版 App 验收：独立名称、数据目录和 30156 / 30157 端口，从原 Electron 入口启动本地服务。验证首次生成自动弹窗、正文及右侧星流科技图标、发布建议、关闭重开、刷新后手动恢复、最大化/还原、重复内容一致和原生 1024 × 768 窗口无横向溢出。验收时发现并修复了首次空工作台成果未自动打开的问题：已加载的空会话列表现在建立空成果基线，刷新时仍避免自动打开历史成果。
- 1600、1024 和 390 像素宽度下检查布局；较窄窗口折叠为单栏，无横向溢出，全部图标加载成功。
- 在隔离的本地招聘网页中，通过浏览器填写并提交整份 JD；保存后的标题、正文（统一表单 CRLF 换行）、部门、地点和人数与成果一致。
- 本轮未调用真实模型执行发布，也未重装桌面 App。浏览器模型的完整线上执行不计入此次验收。

App 验收使用忽略目录 `build/electron-acceptance/app/` 中的副本及独立依赖/开发缓存；仅副本的启动名称、目录、端口不同，业务代码与此 worktree 一致。这是 Electron 开发版运行验证，未重新打包安装版。截图和运行报告在 `build/electron-acceptance/`。关闭验收 App 后，其启动的服务与演示目录正常清理；原安装版关键文件哈希、修改时间、App 和后台服务进程启动时间均未改变。

本次预览和截图放在忽略目录 `build/jd-preview/` 与 `build/jd-design/`。独立预览使用 30146 / 30147 端口，没有停止或替换原安装版服务。
