## 目标与范围

把当前已有能力放进设计稿的视觉和信息布局中，维持现有演示链路、数据来源、按钮效果及状态语义。

本次覆盖 AI 洞察窗口和人才招聘应用中的招聘进展页，以及两者必要的导航和详情衔接。岗位管理、候选人详情、连接配置、空状态和错误状态沿用同一视觉语言；它们没有完整设计稿，不宣称逐像素复刻。桌面首页、Dock、应用市场、飞书、JD 编辑器、外部招聘网站不在本次视觉改版范围内。

## 已核实的现状

### AI 洞察

- 桌面卡片、通知和招聘页面可以打开洞察；目前通过 `AgentDesktop.openInsightResult` 打开单份文件预览，没有设计稿中的独立左侧洞察列表。
- 洞察条目已有标题、摘要、时间和文件身份；使用当前工作台的洞察来源，不增加第二套持久化数据。
- 招聘演示报告保留评价分歧数字、候选人评价证据、标准建议和安排会议入口。报告由 `lib/presentation-progress.ts` 生成；其他来源的招聘报告还有独立 HTML 渲染器。
- `RecruitingInsightPreview` 保留隔离的 HTML 预览和受限会议操作桥接。演示日程和其他来源的本地日历行为有区别，视觉改版不能将它们互换。
- `RecruitingPublication` 已处理 JD 发布建议、确认、进行中、完成与失败；完成后联动人才招聘，不等同于设计稿中的一条持久化“岗位已发布”洞察。

### 人才招聘

- `HRRecruitingApp` 有招聘进展、候选人、岗位管理、招聘应用四个入口，以及在招岗位、连接状态、手动创建和候选人详情。
- 演示数据由 `RecruitingPipeline` 呈现，累计指标和当前状态分别统计；支持阶段筛选、搜索、评价缺失筛选、候选人档案、打开岗位网页、查看洞察和安排会议。
- 未发布岗位、未连接数据、请求失败等状态已存在，不能用 Figma 示例数据覆盖。

## 建议的实现方式

1. 统一这两个应用内的视觉参数：浅灰窗口栏、浅薄荷侧栏、白色内容区、绿色选中态、圆角卡片、细边框、较大的标题和更舒展的间距。AI 洞察参考侧栏 260px、内容内边距 28px、外框圆角 28px；招聘页参数单独核对。按实际窗口尺寸自适应，不把设计画布宽高硬编码为运行限制。
2. AI 洞察采用“左侧洞察列表 + 右侧所选内容”。桌面卡片、通知和招聘页打开时选中对应条目，列表切换复用现有报告。保留全文、证据和原有行动入口，报告按同一视觉语言组织为摘要、证据、建议行动等卡片。长内容滚动查看。
3. 招聘进展采用设计稿的侧栏分组、目标标题、横向指标卡片、候选人表格和状态胶囊。沿用现有岗位和候选人数据；保留累计指标与当前状态的区别，并保留搜索、缺评价筛选、档案、洞察和会议入口。
4. 复用现有 `DesktopWindow` 窗口控制和组件边界。样式限制在目标应用中，避免修改共享样式时连带改变 CRM、投资管理等应用。实现可抽取小组件，但不更换 UI 框架或重写数据层。
5. 字体优先使用现有系统中文字体栈；Figma 中出现 PingFang 与 MiSans，不擅自引入无来源字体。图标复用外形匹配的现有组件，否则取设计导出的正式资产并本地保存。

## 已确认的差异及处理决定

| 差异 | 推荐决定 |
| --- | --- |
| AI 洞察稿左侧是面试偏差，右侧是岗位发布结果，内容不对应 | 将该稿作为列表与详情的布局规范；选中面试偏差就展示原有偏差报告。暂不新增“岗位发布结果”洞察类型；如果要求这一类型，则另行明确它在发布流程中的位置。 |
| 招聘稿使用人才库、初筛、技术面、终面、Offer；演示使用累计进度和七种当前状态 | 保留现有统计和状态语义，套用视觉；不将“面试结束”改名为“终面”，也不虚构 Offer。 |
| 设计稿只列招聘进展和岗位管理，当前还有候选人及招聘应用 | 保留这两个现有入口，使用同样的侧栏样式。招聘进展首屏可突出重点记录，但必须能查看全部、筛选、搜索。 |
| 稿中写官网与 BOSS 已同步，列出多个示例岗位、固定人数、相对时间和已连接数据 | 使用现有真实或演示状态；未发布渠道不显示成功，未连接来源不显示已连接。数字和时间从数据派生，清除设计说明式占位文案。 |
| 设计稿没有详情、错误、加载、小窗口和深色内容版本 | 按相同视觉补齐必要状态；以设计稿浅色应用为主要目标，在深色桌面中保持可读。窗口内滚动和自适应布局保留完整功能。 |
