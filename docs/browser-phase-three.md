## 如何自然触发

`lib/browser/business-sites.ts` 只登记招聘网站的名称、地址和用途，通过 `browser_task.promptGuidelines` 组装进主 Agent 系统提示词一份；工具 description 仅保留通用浏览器工具说明，不再重复注入招聘配置。统计口径、查询步骤、结果格式和简洁性等招聘专用指令已移除，由 Agent 理解问题并从页面获取业务含义。Syntropic 主 Agent 的系统职责允许从已登记业务入口直接委派，不要求用户先提供网址或说“使用浏览器”。

这是可用应用的上下文配置，不是用户 prompt 偷加动作指令、关键词拦截器、固定答案或预演动画。主 Agent 仍自主解释意图并调用已有工具；浏览器 Agent 从真实网页确定筛选控件和每一步操作。上下文不含 seed 人名、统计数字或数据文件路径。纯招聘知识问答、JD 撰写或用户明确指定别的系统不应路由到此网站。

新对话会加载当前入口。开发期间如果已有会话载入过旧版本工具，先结束正在运行的任务，再通过界面“新对话”加载新定义；不要修改原会话数据。若 HMR 导致旧对话面板未同步，先刷新窗口再核对历史。

浏览器模型保持 **`openai-codex / gpt-5.6-luna`**，low thinking；主 Agent 模型未修改。缺授权时继续使用第二阶段现有 Pi 登录入口，不复制其他应用的凭据。

## 首选短场景：单岗位面试收尾进度

在 Electron 底部 Syntropic 输入框发送：

> 帮我看看 AI Agent 工程师岗位，面试结束了多少人，还有几人的评价没齐？

主 Agent 自动委派；浏览器从职位页面读取面试结束统计，并通过页面已有的“面试结束且缺评价”快捷入口取得筛选人数；主 Agent 简洁回答两个人数。此任务不需要逐人打开详情，也不扩展到其他招聘指标。所有结果均来自本次网页交互，初始数据预期为“面试结束 12 人，其中 3 人评价未齐”。

时间按用户发送到主 Agent 最终汇总计算，包含委派、页面加载、浏览器执行和主 Agent 回复，不只计算浏览器任务时间。用户已确认约 33 秒可以接受，因此采用此短场景，不以严格 30 秒为验收门槛。当前仅保留数据源说明的版本，服务正常时三轮实测均成功，总耗时约 23.9、22.7、33.1 秒；此前详细指令版本为 33.2、35.0 秒。实测见验收文档，小样本不代表稳定时限或长期成功率。正式展示前打开并确认两个本地服务正常，在界面开始新对话并等待输入框就绪，不需要预载候选人数据或答案。

## 扩展场景一：进展与缺评价名单

在 Electron 底部 Syntropic 输入框直接发送用户原句：

> 查看 AI Agent 工程师岗位的招聘进展，找出已经结束面试但还缺少评价的候选人，整理名单。

无需先打开招聘网页、无需提供网址、无需提及 Agent/browser。主 Agent 整体委派，浏览器窗口自动打开并前置。若需要更大画面可点击浏览器窗口的“+”最大化。任务结束后点击“对话记录”查看主 Agent 汇总。

重置后的核对基准：

| 招聘目标 | 累计投递 | 累计简历通过 | 累计进入面试 | 面试全部结束 | 当前通过 | 当前失败 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 6 | 30 | 24 | 18 | 12 | 7 | 2 |

| 候选人 | 编号 | 缺少的已提交评价 |
| --- | --- | --- |
| 林然 | NF-1001 | 团队面试，TIM，未填写 |
| 许宁 | NF-1002 | 专业面试 Mark、团队面试 TIM，均未填写 |
| 苏悦 | NF-1003 | 团队面试，TIM，只有草稿 |

这些是初始 seed 的**验收基准**，不注入任何 Agent prompt。数据修改后应以页面为准。

口径已与用户确认：候选人的所有已安排面试都结束，且至少一轮评价未提交；草稿算缺少。某轮已结束但另一轮仍待面试的候选人不列入。网页支持组合筛选，并在每个候选人详情显示各轮状态。

## 扩展场景二：真实填写与保存

在同一对话发送：

> 给 AI Agent 工程师候选人林然 NF-1001 补齐团队面试评价：评分 4 分，意见“能清晰拆解 Agent 可靠性问题，具备生产项目经验，建议通过”，结论“建议通过”，正式提交；然后将最终招聘结论标记为面试通过，决策说明“全部面试评价已齐全，符合岗位要求”。保存后重新打开详情核对，并检查缺评价名单是否更新。

预期浏览器实际选择评分、填写意见、提交评价、保存最终结论，并重新读取页面。林然的两轮评价齐全、最终状态为面试通过；缺评价名单变为 2 人，通过数变为 8，前四项累计数字不变。主 Agent 不代替面试官编造评价内容。

这个任务只操作虚构数据，没有邮件或通知。只读演示不会自动执行这一步。

## 停止、人工操作和重置

- 执行期间专用页面禁止人工导航／填写。点击“停止任务”中止后续动作，或者关闭该任务的专用标签页；不会改去操作相邻标签页。
- 停止不能撤回已经发出的提交请求，需从网页核对状态。第二阶段的独立 Chrome 实例、profile、固定 target、30141 隔离和工具白名单均保持。
- 任务结束／停止后页面恢复已有 shared 控制，可人工继续核查；本期没有新增“暂停后由 Agent 恢复同一任务”的人机交替协议。
- 人工浏览可在 App 浏览器新建标签，输入招聘网址。已打开的其他页面需要刷新才能看到别处最新保存结果；陈旧表单不会覆盖新版本。
- 招聘网站侧边栏“系统设置”→ 数据管理 → 勾选恢复范围 → 恢复初始数据。重置后可用相同原句再次演示。重置不会清理 Pi 会话、模型授权或其他工作台内容。

现有 Dock“人才招聘”是前两阶段之前的工作台业务模块；本期新增的是独立网站，通过浏览器和主 Agent 使用。没有将旧业务模块的数据冒充为新网站结果。

## 保存与独立部署

本地使用 `apps/recruiting/.data/state.json`，由招聘服务统一保存。独立 Agent profile 不共享浏览器本地存储，因此这里没有使用 localStorage 假装跨任务保存。

独立部署入口、Vercel Root Directory、账号权限、`DATABASE_URL`、`PUBLIC_ORIGIN`、Neon 初始化与运行期限制见 [招聘应用 README](../apps/recruiting/README.md)。云端不能自然继承本地文件；缺数据库配置会明确失败。本次没有发布、修改线上官网或创建付费资源。
