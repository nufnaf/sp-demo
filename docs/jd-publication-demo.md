## 演示流程

1. 双击更新后的 `~/Applications/Syntropic.app`，等待本地工作台和招聘网站就绪。
2. 按原流程生成 JD，保存到当前工作空间。可用：

   > 请生成一份高级 AI Agent 研发工程师的招聘 JD，招聘 6 人，北京 / 上海办公，重点是 TypeScript、工具调用、Agent 评测和工程可靠性。保存为当前工作空间的 senior-agent-engineer-jd.html，正文使用正式招聘文案。

3. 点击桌面“最近成果”中的 JD，在成果窗口查看。约 1.4 秒后右上角出现“AI 主动洞察：已识别新创建的 JD”，点击“发布岗位”。不需要在用户话术中指定浏览器。
4. App 自动打开新招聘网站的发布表单。主 Agent 委派 Luna，Luna 真实填写岗位名称和 JD，核对招聘人数、地点并提交。
5. 网页确认保存后，自动打开原来的“人才招聘”窗口，在岗位管理中展示新职位。岗位名称、地点、招聘目标、候选人数读取实际保存结果。点击卡片可打开实际职位网页。

“保存到桌面”可能被 Agent 理解成 macOS Desktop 目录，因此上面明确使用“当前工作空间”。不需要为本演示运行额外的预览服务器。通知支持 HTML、Markdown 和文本 JD，文件名或任务名称包含 JD / 职位描述 / 岗位描述 / 招聘简章即可。

## 哪些是展示，哪些真实执行

- **通知是 mock 场景触发**：查看符合命名条件的 JD 成果后弹出，不实现通用行为预测、任务语义分析或自动发现引擎。
- **内部发布是真实执行**：按钮传入当前成果的文件引用。主 Agent 调用 `browser_task({url, task, jd_file})`，只输出简短发布目标和路径；工具校验当前工作台路径、内部招聘发布页与发布标识，读取文件并提取完整正文，直接交给浏览器 Agent。HTML 解析不运行脚本、不访问外部资源，过长正文报错而不截断。网页填写、提交、保存和结果核对都由浏览器完成，没有调用招聘业务写入 API 或直接修改数据文件。
- **BOSS 只保留展示标签**：“BOSS 直聘 · 已发布”是录屏场景中的 mock 状态，不访问 BOSS、创建账号、登录或发送职位。内部保存成功不能解释为真实 BOSS 发布成功。
- **原人才招聘窗口保留**：新增已发布职位结果卡片，既有候选人管线和应用连接界面不整体迁移。新增职位没有虚构的候选人进展，开始时为 0 人。
- **数据只有一份**：网页保存到招聘应用现有 store。`GET /desktop/published-jobs` 提供本次功能创建的岗位投影，工作台 `GET /api/apps/internal-recruiting` 只读转接供原生窗口展示；没有桌面写入端点。原有 seed 职位仍在招聘网站中，不复制成另一套管线。
- App 专属工作台主 Agent 默认 `openai-codex/gpt-5.6-luna`（low）；普通 Web 保留原配置；浏览器固定 `openai-codex / gpt-5.6-luna`，未增加模型选择或回退。

同一工作空间、同一路径的 JD 使用稳定发布标识。重复点击会通过网页核对已发布岗位，避免重复创建；如果修改同一路径的 JD，当前演示仍返回原岗位，不实现自动更新已发布内容。想演示另一份新 JD，可换文件名；想重复演示同一份发布过程，先按下面重置招聘数据。

## 重复演示和停止

- 招聘网站“系统设置 → 恢复初始数据”会移除新岗位并恢复招聘 seed；只影响招聘应用。Pi 会话、模型、成果文件和其他桌面应用不重置。
- 每次打开 App 后重新查看 JD 即可再出现通知。同一页面生命周期内，已关闭或成功处理的同一成果不会反复弹通知。重演时可退出再打开 App；无需重新生成 JD。
- 浏览器运行中可“停止任务”，停止后可以人工操作。已发出的保存请求可能已经完成，停止不会撤销网页写入。
- 正常成功才自动展示人才招聘结果。若用户已切换窗口、工作空间或接管，不抢回焦点；可自行打开人才招聘的“岗位管理”查看已发布岗位。
- 后台成果窗口暂停文件变化监听，重新前置时重新读取内容；桌面和浏览器窗口共用同一条浏览器事件连接，避免 JD 成果、文件窗口、任务对话和浏览器同时打开时耗尽本地 HTTP 连接。
