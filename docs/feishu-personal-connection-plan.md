# 飞书个人连接与启动准备

状态：已按用户确认的启动前置流程实现，本地验证完成；真实账号端到端验收待进行。基线：2026-09-12 的 origin/dev（3fb074b）。
工作分支：codex/feishu-personal-connection。

## 已确认的体验

首次打开 App，先展示“演示前的一次性准备”：连接飞书、辅助功能、屏幕录制三项。点击「连接飞书」后，连接页把飞书的连接地址交给系统浏览器打开，不再以 App 内二维码为主路径：浏览器已有飞书登录态时，直接在网页里创建或选择连接应用、确认权限并完成账号授权，全程不需要用手机扫码。授权随后自动准备工作资料；两个系统权限由 Electron 实时检查，仅在点击对应按钮时请求并打开系统设置。三项全部完成才挂载现有桌面；后续启动复用授权和资料，仍检查权限是否有效。页面只保留简短操作提示和飞书桌面客户端需登录同一账号的提示；自动创建内容、日程清理边界及权限用途移到随包《使用说明.txt》。

权限按官方 CLI 的全部业务域申请（`auth login --domain all`），使浏览器上的授权页一次列出完整权限供使用者确认；此前只申请写死的少数 scope，导致使用者看不到权限确认步骤。旧的本地二维码生成随之移除：官方 CLI 只在服务端产出二维码图片，无法作为可随时唤起的备用入口，浏览器打不开时改由页面上的链接兜底。

以后启动复用授权及资源，只检查连接、资料和独立日历，整理本轮日程。授权失效回到连接页，网络或准备失败留在前置页重试。不会出现“已进入工作台但关键资料尚未准备”的中间状态。

这是一个统一的个人连接方案，不保留默认专用应用与个人账号两个模式。安装包不再携带专用飞书 App ID / Secret 或固定文档 ID。

## 保留的展示链路

星流科技的业务故事、固定 JD、招聘网站、Browser Agent 发布和候选人查询保持原样。飞书里仅业务介绍有预置正文；周报、电子表格、多维表格和 FAQ 知识节点保留真实类型与空内容。

GUI 安排会议仍由电脑操作真实飞书客户端，再通过同一账号、同一独立日历的 API 核验。CLI 授权不能登录飞书桌面客户端，使用者需要自行登录同一账号。不会改成 API 代替 GUI 提交。

## 数据和生命周期

- 授权由固定版本官方 CLI 管理。应用配置和资源清单位于稳定的应用数据目录，不借用系统默认 CLI 配置，不进入每轮清理的工作目录。
- 资源清单按应用和用户身份绑定。创建步骤逐项持久化，丢失创建回执时先核对资源，不能重复发起不确定的创建。
- 桌面、资料阅读工具和日历共用资源清单。文档正文保留白名单，仅业务介绍可读；列表不会搜索或合并个人其他资料。
- 独立私密日历记录唯一归属描述，启动时检查 owner/shared/归属后才允许重置。只删除具有 Syntropic 标记的日程，不操作主日历，不邀请其他人。
- 当前运行绑定一个账号，进入工作台后不能在本轮重新授权成其他账号。其他账号从新的启动流程开始，防止缓存和已提交的电脑操作跨账号复用。
- 资料编辑跨启动保留；已经移除的资料不静默重新创建。

## 浏览器优先的授权调整（2026-09-12 追加）

使用者反馈两处问题：连接过程先要手机扫码、且看不到权限确认步骤。核对官方 CLI v1.0.95 源码后确认：`auth login` 不带 `--scope` 时默认申请全部业务域，旧实现写死了 7 个 scope，所以飞书没有可确认的权限页；`config init --new` 与 `auth login` 都只把地址写入输出，需要调用方交给系统浏览器。

- `startFeishuLogin()` 改为 `auth login --domain all --no-wait --json`。
- 移除本地二维码生成与 `FeishuAuthFlow.qrCodeDataUrl`；`browserUrl()` 只放行 feishu.cn / larksuite.com 的 https 地址，避免任意地址进入系统浏览器。
- 连接页在点击「连接飞书」后打开系统浏览器，并把二维码视觉换成“浏览器授权窗口已打开”；浏览器未打开时页面链接兜底。App 自行发起的授权步骤（配置完成转授权）延迟片刻自动打开。
- 会话中途授权失效的兜底页面（`FeishuAppView`）同步改为浏览器授权；该路径仅在未使用演示工作目录时可达，打包演示包中实际由启动页门禁接管。
- 《使用说明.txt》第 1 条改写为浏览器流程。

验证与边界：

- 单测与浏览器门禁通过；`npm test` 中除本分支既有的 26 项无关失败（insights、publication、task-window、subagent 等）外无新增失败。
- 全部业务域是否触发组织侧审核取决于租户的高敏权限策略，未经真实账号验证；若授权页提示审核，可退回 WorkBuddy 使用的 `--recommend --exclude vc:meeting.realtime:read`。
