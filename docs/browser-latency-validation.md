# Browser Agent 完成轮次优化

## 改动

`browser_finish` 已经保存了结构化的核查结果，旧流程仍让 SDK 继续请求模型生成收尾回复，然后才向主 Agent 返回。现在在创建专用浏览器会话时设置 SDK 的 `shouldStopAfterTurn`：已收到结果就结束当前工具轮次，不再请求收尾回复。使用正常完成机制，不触发用户取消或把任务标为 stopped。

只有真正执行了完成工具才满足结束条件；完成工具失败不会提前结束。缺少结构化结果时，原有仅开放完成工具的一次补交机会保留。所有网页操作、保存核查、专用页面隔离及停止操作保持原流程。

未调整主模型、浏览器模型、thinking level、业务网站提示词、网页内容或招聘数据，也没有加入预设操作。仍为用户原问题 → 主 Agent 委派 → Luna 读取真实页面并操作 → 主 Agent 汇总。

## 分段计时

任务状态的 `timings` 提供每段耗时（毫秒），仅记录阶段名称和持续时间，不记录账号、密钥或模型思考内容：

- `auth`：创建模型运行时与校验授权。
- `browser-start`：创建任务专用浏览器并连接执行器。
- `navigate`：打开入口页。
- `snapshot`：读取可访问性树并同步页面状态。
- `session`：创建浏览器 Agent 会话。
- `model`：从模型轮次开始到完整助手消息结束；含请求准备、网络等待和输出生成，不是纯推理时间。
- `action`：网页动作实际执行。
- `cleanup`：结束执行器。

初始打开网页及快照读取仍不计入 `steps`，`turns` 统计浏览器模型轮次。各段之和与任务 elapsedMs 之间可能有少量宿主处理间隙。主 Agent 委派与最终汇总用会话时间戳单独测量。

## 自动验证

新增测试使用真实 Pi SDK 会话循环，替换模型传输为测试内存事件，不访问模型网络或真实账号：

- 成功结果：一次动作、一次完成，总共两次模型请求，结束后不再请求模型。
- 明确阻碍：completed=false 同样正常结束，无取消消息。
- 完成工具抛错：循环继续，下一次成功提交后才结束。
- 用户取消：仍可终止等待，不生成成功结果。

以上 4 项通过；原有浏览器协议、页面控制和业务上下文测试 7 项通过。TypeScript、修改文件 ESLint 和 diff 空白检查通过。
