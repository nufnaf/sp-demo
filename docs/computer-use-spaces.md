# Computer Use 与 App 内 Spaces

2026-09-11。工作树 `computer-use-desktops`，分支 `codex/computer-use-desktops`，创建时基于 dev `981660f`。采集与输入的可行性、对照实验和复用来源见 [Phase 0](./computer-use-phase-zero.md)。本文记录后续接入，不能替代最终安装版或真实日历保存验收。

## 已接入的产品行为

- 菜单栏“飞书实时画面”打开 App 内画中画；会议任务开始也会自动打开。默认宽 350px、高度随原生画面比例变化，放在桌面右下角。无外层标题栏、交通灯、步骤栏或黑边。
- 悬停、键盘聚焦控制按钮时显示隐藏、暂停/继续、放大、打开飞书和更多选项；触屏直接显示控制。运行中默认只看画面，暂停、核验、完成、失败及停止时保留业务状态提示。隐藏小窗不停止任务。
- 拖动画面到页面顶部会展开桌面总览，可以直接拖到“新桌面”；更多选项中的桌面菜单提供键盘可用的移动入口。放大仍在 App 内观看，保留画面比例，并给底部助手输入框留出位置，再点还原恢复小窗位置。
- “打开飞书”经同源、仅本机的 `/api/computer/open` 明确激活固定 bundle ID `com.electron.lark`；只在用户点击后调用 macOS `open -b`，不接收任意路径，不重启客户端，也不添加目标 App 启动参数。模型工具不包含此动作。
- 新建、切换、关闭最多六个内部桌面；关闭桌面时窗口移到相邻桌面。每个桌面保留各自的前台窗口，已有窗口再次打开时回到其归属桌面。桌面布局单独保存在当前 App 的 localStorage。
- Spaces 与工作台数据范围分开；没有创建或切换 macOS Spaces。Control + 左/右/上提供页面快捷键，macOS 若先拦截系统快捷键，可使用菜单栏桌面总览。
- 窗口跨桌面移动、隐藏时保留 DOM 和帧订阅。关闭预览会释放查看订阅，但正在执行的会议任务继续。重新打开会观察同一任务。

## 执行与核验

`SYNTROPIC_COMPUTER_USE=1` 且 macOS 时，现有 `scheduleFeishuAlignmentMeeting` 进入 GUI 编排。普通 Web 环境保留既有 API 行为；启用 Computer Use 后，GUI 失败不会回退 API 创建。

Next 进程中的单例管理一个独立 Node worker，worker 同时拥有 Cua 操作上下文和共享采集租约。页面通过 `/api/computer/events` 接收状态和画面，不直接导入原生模块。预览读取当前采集帧，不重新观察 AX，因此不会使模型持有的快照 token 失效。多个查看者共用同一 worker；没有任务和查看者时自动关闭。

模型采用 AX 优先、需要定位时查看截图的工具循环。当前模型默认 `openai-codex/gpt-5.6-luna`，可用 `SYNTROPIC_COMPUTER_PROVIDER` / `SYNTROPIC_COMPUTER_MODEL` 指定已授权的视觉模型。它复用 Pi 的模型与认证服务，只加载本任务原生工具。开发诊断可显式设置 `SYNTROPIC_COMPUTER_TRACE_DIR`；不记录认证配置、截图或模型思考内容。

只进入本次新建的日程编辑器；已有未保存日程会停止。飞书把空标题占位词“添加主题”放进 AX value，需要单独识别。内容输入前必须确认目标共享日历已选中。实际参会人区域不允许操作，名单仅写入说明。普通操作工具不能点击保存；保存工具先独立检查标题、日期、提交后的时间、可见说明、所选日历和参会人区域，暂停恢复后在保存前再次读取核验。

原生日程保存没有 API 幂等键。因此保存前先持久化“可能已保存”的边界，随后只点击一次保存；保存后通过指定日历 API 匹配完整内容。丢响应、worker 中断或 API 暂未同步时，后续请求只重新读取，不重复点击保存。只有 API 核验匹配后，现有会议卡片与任务进度才获得成功结果。

GUI 创建的说明使用“由 Syntropic 安排”作为完整行归属标记。原有启动重置同时识别它和旧内部标记，只在已配置的演示日历中处理；不会按标题或文中的零散提及判断归属。本轮没有运行日历重置。

## 2026-09-11 小窗时机与连接恢复

自动显示取决于模型工具成功读取或操作目标窗口后的 `interactionStarted` 状态。任务创建和模型前的初始观察不会自动打开小窗，手动查看入口保留。

录屏帧读取和窗口绑定、释放共用驱动队列，帧携带窗口身份，避免新建日程窗口切换时读取已关闭的旧录屏连接。UI 遇到短暂错误会保留上一帧并标记恢复状态，1.5 秒仍未恢复则清空；持续无新帧同样会清空。重连会在精确目标窗口上重建录屏连接、使旧操作快照失效，不会重放输入。

驱动测试复现了旧连接释放与取帧的竞争，并验证断开后重建与旧快照拒绝；浏览器 fixture 验证自动打开时机、短暂和持续错误、窗口切换、重连以及原有 Spaces/暂停/停止交互。用户当次黑屏没有对应追踪记录，因此不能确定当次只有这一原因，也不将上述 fixture 验证视为真实模型完成日程的测试。

## 2026-09-11 小窗与应用层级

飞书预览属于独立悬浮层。Spaces 的 focus/move 仍管理它的桌面归属和显隐，但不会将它写入普通应用的 front；点击、打开、移动小窗均保留各桌面原来的前台应用。任务完成只更新结果，不改变洞察窗口的显示或焦点。此规则同时覆盖自动打开、手动重新打开、拖拽、菜单移动以及跨桌面切回。

回归在修复前复现了小窗出现即让洞察失去置顶的问题；修复后检查真实 React/CSS 的置顶状态和命中窗口，并保留原来的暂停、隐藏、重连及 Spaces 用例。所有业务接口使用 fixture，不重复安排会议。
