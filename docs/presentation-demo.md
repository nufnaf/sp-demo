## 演示步骤

1. 双击 App，进入招聘工作台。当前任务、最近成果与 AI 洞察为空；Dock 已固定飞书、人才招聘、成果、浏览器和日程。
2. 打开飞书 →《星流科技业务介绍》。列表与正文来自飞书官方 API，不是本地预设文本。
3. 输入：“请根据飞书中的《星流科技业务介绍》，生成 AI Agent 工程师的岗位 JD，作为可打开的文件放在工作台中。”真实 Agent 读取资料，生成本轮 `ai-agent-engineer-jd.html`。
4. 打开生成成果。约 1.4 秒后出现发布建议。它与其他洞察共用一个右上角通知位，发布动作优先；从任意入口打开对应洞察后会标记已读。这里全部是 App 内通知，Electron 演示不申请系统通知权限、不发送系统任务完成通知。点击“发布岗位”。
5. 观察 App 内浏览器真实填写名称、完整正文与必要信息，提交并核对成功。执行可停止或接管。完成后正常返回原人才招聘窗口；用户主动切走时不抢焦点。
6. 本轮保存的岗位自动关联演示候选人。查看招聘管线、搜索姓名、筛选阶段或“面试结束且缺评价”，打开档案查看评价与历史。原窗口和网页来自同一份记录。
7. 输入：“帮我看看 AI Agent 工程师岗位，面试结束了多少人，还有几人的评价没齐？”Agent 必须从这次实际网页读取并汇总。初始预设为面试全部结束 12 人，其中 3 人评价未齐；草稿算未提交，仍有未结束面试的人不计入。
8. 查看“面试官标准不一致”洞察。评价已齐的 9 位候选人中，3 位的 Mark / TIM 推进判断相反。通过洞察或管线安排对齐会议，在团队日程查看标题、参会人和议程。此步骤为本地模拟，不发送邀请、消息或邮件。
9. 刷新窗口确认本轮进度仍在。macOS 红色关闭按钮只关窗口，从 Dock 可恢复；用 ⌘Q 完全退出。
10. 再打开，确认没有上一轮任务、JD、洞察、发布或招聘修改；重复步骤 2–9，应再次展示完整填写发布过程。

## 数据恢复与边界

每次 Electron 进程启动创建 `~/Library/Application Support/Syntropic/presentation-runs/<uuid>`（开发版为 `Syntropic Dev`）。其中包含工作目录、Agent 会话、应用状态、浏览器资料、招聘数据与模拟会议。Electron 使用本轮独立内存分区；刷新与关闭窗口不清空分区。

完全退出时独立 supervisor 停止自己拥有的服务及后代进程，确认停止后才删除该轮目录。Electron 异常退出会通过 IPC 断开触发同样清理；整机断电或 supervisor 同时被杀时，可能留下孤立目录。下一次总用新目录，不载入这些残留；未知旧目录不自动删除，避免仍有进程写入时误清理。

`~/.pi/agent` 原历史、模型设置与授权仍由 Pi 原机制管理，不复制到演示目录或安装包。凭据正常刷新可能更新其授权存储，退出恢复不删除授权。专用飞书配置位于忽略的本机文件及受控包资源，不属于演示运行目录。

普通 `npm run dev` 继续原 Pi / 浏览器持久化；独立 `npm run demo:recruiting` 继续 `apps/recruiting/.data` 或自行配置的数据库，重启保留。不设置演示环境变量就不注入本轮候选人关联或退出清理。
