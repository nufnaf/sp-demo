# JD 正文生成与浏览器预启动

当前安装版已更新为 `5748d921-5c5c-4286-9a0c-ac486e6d9739`，新增正文限长与任务指令精简；最新两轮见 [实测记录](prompt-length-audit.md)。下方保留各阶段的历史结果。

## 实现范围

按用户确认保留真实大模型 JD 撰写，改为固定 HTML 模板排版；在 Syntropic 桌面首次可见后提前准备一个独立 Chromium。真实任务委派沿用 dev 基准的 Pi 能力，没有切换为 mock，也没有改成业务 API 发布。

### JD

招聘工作台后台 Agent 仍调用真实飞书列表/正文工具，根据本次正文撰写 title 与 sections，交给 `save_recruiting_jd`。模型只输出业务内容，模板负责 HTML、CSS、转义与打印/窄屏布局。保存工具写入临时文件、读回核对、检查取消信号，再原子替换 `ai-agent-engineer-jd.html`；不跟随已有目标文件的符号链接。

模板只含排版及星流科技品牌文字，不含预写职责或要求。正文仍包含公司背景、岗位信息、岗位职责和任职要求，不包含待确认事项、内部审阅待办或面试官安排。成功保存的工具结果进入原成果识别链路；任务、成果、查看后的发布建议以及完整文件引用交接保持有效。普通工作台、普通 Web 和原 Pi 工具不被替换。

### Chromium

`AgentDesktop` 挂载且 document 可见后，经过两帧调度调用受同源限制的 `/api/browser/prepare`。服务端只使用 App 专属招聘工作台，不接受客户端提供路径/URL。只启动一个全新 Chromium、独立配置目录和空白页，完成连接隔离准备，不调用模型、不导航业务网站、不启动执行器、不发 `browser.opened`，不抢焦点。

刷新或组件重复挂载不会创建多个预备实例。第一个同工作台浏览器任务在 await 前原子领用；并发/后续任务仍启动独立浏览器。跨工作台不领用；失效或关闭的预备实例按原冷启动路径回退一次，不让任务接管未知页面。本版本不自动补充浏览器池。

准备记录由 `/api/browser/state` 的 `warmup` 提供，并关联到领用任务；后台 `warmup.timings` 与点击后的 `startupTimings` 分开。后台成本只是前移，不计作消失或从总资源成本中扣除。领用时仅记录 `prepared-browser-wait`，不会把已完成的后台 Chromium 启动时间再次加进点击耗时。

未领用 Chromium 仍属于 App 启动的本地服务子进程树，退出由原 supervisor 先停止全部已跟踪子进程，再清理本轮目录。macOS 关窗口不等于退出；重开窗口/刷新不补充预备实例。普通 Web 没有自动预启动。

## 后续：JD 正文长度预算（2026-09-09，已安装验证）

为避免正文长短变化放大模型生成和浏览器填写的时间，新增目标 900–1100 字符、硬上限 1200 字符。统计模型提供的 title、所有 section heading/content，按 Unicode code point 计数，含标点、空格、换行；不含 HTML/CSS、模板额外品牌文字和节间排版分隔。因此这里的计数与上表从 HTML 提取的最终发布文本长度略有差别。

专用 JD 后台合同与保存工具要求精简重复表述，保留公司背景、部门/地点/人数、岗位职责和任职要求；缺失的薪酬、职级等信息直接省略，内部待办与面试官安排不写入 JD。保存工具在任何文件写入前验证总长度；超限返回当前计数与精简提示，由模型修改后再调用，不直接截断，也不覆盖已有成果。保存成功结果记录 characters，便于后续实测。正文仍由真实模型根据飞书资料生成。

验证：相关 20 项测试通过，覆盖 1200/1201 边界、Unicode 字符、超限不覆盖文件、成果登记和委派要求传递。长度调整已随最新安装版完成两轮真实验证，见页首链接；上文旧安装版及两轮记录属于加长度限制之前。超限重写也可能增加一次模型等待，目标区间为上限留出余量，但不保证固定完成时间。
