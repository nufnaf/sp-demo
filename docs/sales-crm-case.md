# 星流 CRM：真实网站与销售应用连接

线上公司 CRM： https://company-crm-site.vercel.app

独立网站源码：`/Users/heyden/code/company-crm-site`。Vercel 项目为 `hitparks-projects/company-crm-site`。

## 演示路径

1. 打开星流 CRM，使用管理员访问密钥登录。访问说明在本机 `~/.pi/agent/pi-web/星流CRM访问说明.md`，不要把凭据提交到代码库。
2. 打开「集成与 API → 查看连接信息」，复制网站地址和只读访问令牌。
3. 在 Pi Web 的「启动台 → 销售 CRM → 数据源 → 连接公司 CRM」中填写这两项。
4. 首次连接会真实访问网站的 `/api/v1/health` 与带 Bearer 令牌的 `/api/v1/snapshot`，同步客户、订单和跟进。
5. 在公司 CRM 网站编辑一笔订单的已收款金额，或者新增客户跟进。记录保存到 Vercel 私有 Blob；刷新网页、切换设备或重新部署均不会丢失。
6. Pi Web 后台每 30 秒获取远程版本。只有新版本或数据内容变化才更新本地缓存并提交 `crm.data.changed` 洞察事件。页面每 15 秒读取本地同步状态，因此界面通常在 30–45 秒内体现变化；「立即同步」可主动拉取。
7. 后台 AI 分析完成后，桌面洞察中显示报告并通知。报告明确标注演示业务数据。

## 真实边界

- 这是可登录、可编辑、可持久化的真实网站与真实授权 API；初始业务记录是合成演示数据。
- Pi Web 的远程连接采用只读授权。网站负责编辑公司客户、订单和跟进，Pi Web 展示同步数据与 AI 洞察；没有伪造双向写回。
- 原有本地演示来源保留在本机缓存中，但不再作为“已连接来源”或业务数据参与展示。独立手工记录与 JSON 导入仍可使用。
- 远程记录 ID 加 `company-crm:` 命名空间，不覆盖本地客户；同一远程版本重复同步不会重复生成洞察。
- 凭据按工作台存放在 Pi 服务端的私有凭据存储。API 状态与浏览器持久化中不包含令牌。
- 连接异常时显示错误并保留最近一次成功同步的数据。断开连接停止轮询并移除本地远程缓存，不删除公司网站中的记录。
- 后台同步依赖 Pi Web 服务运行；重启后打开相关工作台会恢复同步。
- 接入其他公司 CRM 时，对方需要实现同一快照协议或新增适配器；不宣称任意第三方 CRM 都能直接连接。

## 数据接口

`GET /api/v1/health` 不需要令牌，返回 `status=ok`、`sourceId=company-crm` 和能力列表。

`GET /api/v1/snapshot` 需要 `Authorization: Bearer <token>`，返回：

```json
{
  "data": { "customers": [], "orders": [], "activities": [] },
  "meta": {
    "sourceId": "company-crm",
    "sourceName": "星流 CRM",
    "revision": 1,
    "updatedAt": "2026-09-06T07:00:00.000Z",
    "syntheticData": true
  }
}
```

所有金额使用人民币元，日期为 YYYY-MM-DD。客户阶段：线索、需求确认、方案报价、商务谈判、已成交、已流失。订单状态：执行中、已完成、已取消。JSON 导入格式可以在 Pi Web 数据源页面下载。

## 存储与网络

网站使用私有 Vercel Blob `xingliu-crm-data`，通过强 ETag 和数据 revision 双重校验防止并发覆盖。不会用 `/tmp`、浏览器 localStorage 或进程变量冒充持久化。

连接器仅接受公开 HTTPS 首页地址，拒绝内网地址、跳转与超限响应。直连在 TLS 建连时校验 DNS；配置外网代理时使用用户已有的 HTTPS 代理。macOS 桌面启动的服务会读取系统 HTTPS 代理，不修改系统设置。

## 回款阻塞演示（官网专属）

官网数据围绕云舟制造订单 `SO-26001`：合同 42 万元、已收 30 万元、未收 12 万元；销售两次向财务催款，最新跟进说明验收报告缺少培训附件及签字。其他客户保留正常进展作为背景。

显式连接 `https://company-crm-site.vercel.app` 并完成真实鉴权、同步成功，且远端标记 `syntheticData=true` 后，启动 10 秒的一次性演示计时器。到期从工作台最近的成功同步快照生成报告，写入现有洞察结果存储，复用桌面通知及洞察组件。桌面的现有 5 秒轮询可能再带来最多约 5 秒的展示延迟。

- 每次显式重新连接可重演；普通刷新、手动同步及 30 秒后台轮询不启动演示计时器。
- 重连重置待触发计时，断开连接取消计时；服务重启不重放未完成的演示计时。
- 特殊连接首次同步不再同时排入通用 AI 分析，避免同一连接产生两份报告；后续真实数据变化仍走正常 AI 洞察。
- 报告金额、客户及证据来自同步数据，报告页注明这是预设产品演示案例。如果订单已付清、未逾期或最新跟进不再描述验收缺项，不发布旧案例。
- 其他站点及非演示数据不走这条特殊逻辑。

演示入口：销售 CRM → 数据源 → 重新配置（填写官网只读令牌）或断开后重新连接 → 等待洞察通知 → 点击查看证据、推进建议与沟通草稿。令牌参见本机私有的「星流CRM访问说明.md」或官网「集成与 API」。

官网背景数据扩充为 40 家客户、12 笔订单、76 条跟进。阶段分布为线索 12、需求确认 9、方案报价 7、商务谈判 5、已成交 7；不同联系人、负责人、合同金额和付款进度均可在真实快照中查看。扩充只新增稳定 ID 的背景记录，不覆盖主演示订单。

## 洞察确认后安排会议

回款报告提供“由林一牵头召开验收与回款对齐会”的卡片，读取最新 CRM 参会名单与议程，默认下一个工作日 10:00、30 分钟，可调整时间。只有点击确认才调用 Mac Calendar 写入；参会人和会前材料进入备注，并设置提前 10 分钟提醒，不自动发送邀请，也不声称已核验参会人忙闲。使用当前工作台与订单的稳定标识防止重复创建。

HTML 保持隔离，通过专用 iframe 消息桥访问 `/api/crm/meeting`；仅注册的销售演示洞察可调用。服务器核验来源、报告注册、CRM 数据版本、案例状态和会议时间。日历权限失败在卡片内显示错误供重试。
