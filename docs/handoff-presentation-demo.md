## 本轮重点

1. **预设与重置**：一次运行内修改、保存、刷新正常。完全退出 App 后恢复预设，下次启动不带入本轮任务、JD、洞察、发布岗位和候选人修改。明确 macOS 关闭窗口与完全退出的区别；异常退出后的下一次启动也不能把半轮演示误当新开场。
2. **数据隔离**：只清理专属演示运行数据；保留用户的 Pi 原会话、工作目录、账号授权、模型配置和其他数据。清理前停止本轮执行，避免子进程继续写入。普通 Web、独立招聘网站的保存边界不要无意改变。需要最小的隔离与种子恢复，不建设复杂多租户系统。
3. **飞书可用**：之前本机 `/opt/homebrew/bin/lark-cli --version` 成功，但安装版 `/api/apps/feishu` 返回 installed=false，原因是安装版 PATH 排除了该路径。CLI 本机安装约 41 MB，原生可执行文件约 40 MB。讨论复用本机、随包或首次下载的取舍；只修 PATH 不满足另一台无开发环境机器的完整演示需求。不要把授权凭据打包。预设资料可以模拟，但不能宣称模拟数据来自真实飞书查询。
4. **限定浏览器场景**：用户同意 Demo 阶段强耦合指定招聘查询与 JD 发布。收窄 `lib/jarvis.ts` 的“给网址就走 browser_task”规则，保留资料阅读和 JD 生成的原任务路径。浏览器继续固定 `openai-codex / gpt-5.6-luna`，主模型不变。网页操作必须真实，不用 API/文件修改/动画代替。
5. **统一通知**：用户预期只在原有发布建议的点击后插入 browser use，不增加一层产品通知。基准代码只有通用“AI 洞察已生成 → 查看”，没有静态视频的“发布岗位”按钮；上轮新增了 RecruitingPublication，因此两者共用位置且层级不同。沿用原风格统一通知展示，避免重叠。通知触发可以继续 mock，不做通用预测引擎。

BOSS 保持现有展示标签，不访问、不发送。新旧招聘窗口关系已获同意：旧窗口展示结果，新网站承担真实网页操作。不要因为关联不完整就整体替换旧窗口。跨工作台共享公司数据、修改同一路径 JD 后不更新已发布正文，不属于本轮需要扩展的演示功能；退出恢复预设应保证下次仍能展示完整填写过程，而非只核对重复发布。
