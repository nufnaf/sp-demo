## 人工操作、停止和隔离

- Electron 内人工打开 R-101，粘贴 `HUMAN_PHASE_TWO` 并点击保存，网页和服务端记录一致；后续 AI 操作 R-102 没有修改 R-101。
- 在运行中的只读任务点击“停止任务”，任务进入 `stopped`，步骤保持 2，不再执行；主 Agent 正确回复已停止。界面提示已发出的网页请求不能撤回。
- 在运行中关闭专用标签页，任务明确失败为“目标页面已关闭，任务已终止；不会切换到其他页面。”最终复测任务 `8855fc86-2855-4719-b7f2-f0678fc5e23f` 在 7.190 秒终止，另一页仍保持原 URL 和内容，关闭页没有重现。
- 原生 agent-browser 集成测试同时建立两个独立 Chrome 任务：一页真实输入不影响另一页；人工写入/导航被拒绝；关闭第一目标后读取与导航均失败，第二执行器仍能独立输入；已停止的执行器拒绝后续命令。
- 程序拒绝任务导航到 Syntropic 30141 端口，页面弹窗被关闭。模型不能选择浏览器、切换 target、运行任意脚本或注入协议/命令。没有打开用户日常 Chrome。

开发中发现并修复了三个问题：人工粘贴快捷键被截断；提前中止 Pi 会话导致实际保存后误报失败；关闭页面时较晚返回的读取事件让标签重新出现。前两轮开发任务的失败记录保留在测试对话中，不能算入最终成功样本。另一次早期停止测试在点击停止前已发出保存，因此保留了 R-103 的测试备注；这不作为“停止阻止保存”的证据。

## 已知边界与待验证项

画面复用现有真实 Chrome 截图和输入转发，不是原生内嵌 Chromium 标签。没有实现同一任务的人机交接或继续操作，也没有独立模型选择界面，符合用户最终调整。

本次使用已存在且有效的 Pi 登录；没有退出账号重新走 OAuth。缺少授权的错误与“打开设置与登录”入口复用原有登录流程，未通过删除真实凭据模拟缺失授权。

未验证外部招聘系统、验证码、多窗口登录、文件上传下载、跨任务共享登录和任意网站兼容性。任务 profile 独立且保留在磁盘，新任务不会复用前一次 AI 任务的登录；本地测试站无需登录。网页任务最多 3 分钟、60 步、40 个模型轮次。

当前测试网站数据只保存在该服务内存中，重启测试服务会重置。后续接入招聘系统的位置是 `lib/browser/extension.ts` 的 `browser_task({url, task})`，替换真实 URL 与完整业务任务即可开始针对目标网站验收。
