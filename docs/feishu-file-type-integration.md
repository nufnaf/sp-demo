# 飞书资料列表类型展示

新版飞书布局由 PR #11 合入 dev；本次展示适配接收资料接入层返回的 `type` 和 `readable`。接入代码在 `codex/feishu-calendar-sync` 中推进，本改动不修改凭据、白名单、日历或正文 API。

## 展示约定

| type | 显示类型 | 图标和底色 |
| --- | --- | --- |
| docx | 文档 | 保留原文档图标，蓝色 |
| bitable | 多维表格 | 分层图标，绿色 |
| sheet | 电子表格 | 表格图标，青色 |
| wiki | 知识库 | 书本图标，橙色 |
| minutes | 妙记 | 声波图标，紫色；仅在接口实际返回时展示 |
| 其他 | 文件 | 通用文件图标，灰色 |

只有 `type=docx` 且 `readable` 不为 false 的条目显示正文打开按钮。省略 `readable` 仅用于兼容原先只有授权 docx 的 API；新接口应明确返回 true/false，并把 `documentIds` 限于业务介绍，展示资料使用 `resourceIds` / `wikiNodeIds`。

列表专用条目保留搜索和收藏，不创建外链，不触发正文请求。标题和更新时间来自接口；没有更新时间显示“—”。不填入设计稿中的虚构所有者或时间。

## 集成时保留

- 当前标题右侧搜索框、12px 提示文字、无列表刷新按钮、标题旁收藏按钮。
- 本文件对应的类型映射、图标配色和正文入口判断；日程分支此前基于旧布局的 ResourceLabel / 外链渲染不应覆盖它。
- 日程入口的接入改动按日程分支保留。

## 验证状态

TypeScript、修改文件 ESLint、diff 检查通过。通过日程分支的真实 FeishuDemoClient 读取 5 项资料元数据，再在独立浏览器验证页临时替换列表响应进行渲染检查：docx × 2、bitable、sheet、wiki 的标签和配色正确；只有业务介绍可打开正文，Q3 搜索命中电子表格。

该验证不等于两个分支已完成端到端集成。临时响应替换已清理，验证页已关闭；真实新接入与新配置合入后还需检查正常 API 路径。妙记目前没有真实样本，未做联调。
