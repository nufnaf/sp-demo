# 浏览器任务完成后返回发起对话

## 问题与行为

此前桌面只响应 `browser.opened`：自动打开浏览器，并在专用任务页运行时收起主对话。没有完成后返回发起会话的逻辑。之前验收时打开“对话记录”属于人工核对，不是 App 的自动行为；不能将其当作自动回切已经实现的证据。

本次前端补上返回流程：

- 自动进入 Agent 专用浏览器页时，记录当时的发起会话和页面。
- 该浏览器任务 completed 或 failed 后，返回仍然对应的主对话面板或任务窗口。浏览器页保留，主 Agent 可以继续流式输出汇总。
- 不等待额外模型请求，不修改 Agent 模型、提示词、网页操作或业务数据。
- 用户切换窗口、工作台、会话、关闭浏览器，或在浏览器内操作鼠标/键盘（包括切换标签页、停止/接管）后，取消这次自动返回。
- 用户停止任务不触发自动返回。其他任务的完成事件不影响当前会话。
- 对短暂 SSE 重连，核对已跟随任务的状态；返回请求只消费一次，旧任务不会反复弹出对话。

实现位置：`components/AgentDesktop.tsx`（事件与窗口状态）、`components/BrowserApp.tsx`（用户交互取消自动返回）、`lib/browser/return-to-origin.ts`（会话、页面及窗口对应关系）。

## 自动检查

新增 6 项返回规则测试覆盖：成功/失败、任务窗口来源、人工/未知来源、运行中与用户停止、用户切走、其他任务完成。全部通过。

BrowserApp 原有 4 项检查通过。其中一项仍断言旧的截图 `?revision=` URL，已确认 HEAD 实现原本就是 `cache: no-store`，因此修正该过期断言；没有改变截图请求或刷新机制。

TypeScript、修改文件 ESLint 与 diff 空白检查通过。
