# 飞书连接：首次启动准备

App 统一使用用户自己的飞书账号。首次打开时，前置连接页调用随包的官方 CLI，点击「连接飞书」后把飞书页面交给系统浏览器：在网页里创建或选择连接应用、确认全部业务域权限并完成用户授权；自动准备完成后才进入原有桌面。后续启动复用授权和资料，不再需要维护者登录账号。

启动页提供飞书连接、辅助功能和屏幕录制三个条目；全部就绪后自动进入工作台。页面逐项列出操作步骤和同账号提示；权限项包含系统设置路径、添加 Syntropic、身份验证和重开操作。自动创建内容的详细说明随 ZIP 的《使用说明.txt》提供：星流科技业务介绍（有正文）、本周招聘进展（空文档）、候选人招聘进度（空多维表格）、Q3 招聘计划与编制（空电子表格）、招聘与面试 FAQ（私有知识空间中的空节点），以及独立私密招聘日历。桌面和 Agent 只访问登记的工作资源，正文仍只开放业务介绍。

每轮启动核对日历归属，清理其中带 Syntropic 标记的日程，建立当天两条日程。文档内容跨运行保留，主日历和个人其他资料不会被扫描展示或重置。电脑操作安排会议仍需用户在飞书桌面客户端登录同一个账号。

日历创建返回 `data.calendar`，查询返回直接的 `data`；所有者、私密范围、日历 ID 和工作标记均以查询结果核对。已创建的日历需出现在当前用户日历列表中，不重复调用需要额外 scope 的订阅接口。普通资料或网络错误只提供重新准备；仅明确的 token/scope 错误提供重新授权，避免把数据结构或资源访问问题误报为账号授权失败。

权限由 macOS 实时检查，不在本地存储“已授权”标记。首次点击各项的“打开系统设置”会调用对应授权入口并打开系统设置；返回 App 自动检查。系统尚未使授权生效时，提示用户完整退出后重新打开。浏览器预览没有原生授权能力，会保留列表并提示在桌面 App 中开启。

## 开发和构建

运行 `node scripts/prepare-feishu-cli.mjs` 构建固定 v1.0.95 连接组件。工具链自动下载并校验，CLI 通过公开 transport 扩展使用 App 的系统代理桥接；保留官方认证和权限实现。`package:desktop` 自动执行此步骤，使用者无需安装 CLI、Node、npm 或 Go。

构建时由 `scripts/desktop-usage.mjs` 生成 release 目录的 `使用说明.txt`。封装 ZIP 必须使用该文件（`zip_app.py --instructions <release>/使用说明.txt`），避免采用旧版默认说明。

安装包不再读取或包含 `.env.feishu-demo.json`。旧的 App ID / Secret / 文档 ID 配置不参与运行；CLI 自己创建的应用配置仍由 CLI 管理，不能把“无需手工配置应用”理解成 OAuth 没有应用身份。

稳定存储：打包 App 的 `userData/feishu`；开发默认 `~/.syntropic/feishu`。`SYNTROPIC_FEISHU_HOME` 可用于隔离测试，`SYNTROPIC_FEISHU_CLI` 指定连接组件路径。CLI 配置目录显式隔离；令牌使用官方 CLI 的安全存储。资源清单按应用与用户身份散列存储。授权不能放进每轮删除的 presentation root，也不能复制其他工具的 token。

初次授权申请文档、云空间、日历、电子表格、多维表格创建、知识库和续期权限；若飞书组织需要启用权限，前置页提供官方权限页面及重新授权入口。

## 失败恢复

重新授权按本次 flowId 的完成结果判断，不以旧账号 token 是否有效放行。完成轮询必须带 `--json`，读取 `authorization_complete`。CLI v1.0.95 在已保存新 token、仅部分申请权限未获批时仍返回退出码 3；此时应记录 `missingScopes` 并继续，不能当成登录失败。业务所需权限仍由资料准备及后续 API 操作检查，缺少可选业务域权限不阻止登录。没有本次完成事件、拒绝授权或超时仍会失败。

后台保存等待、成功、失败和过期结果；刷新恢复进行中的授权，准备接口也会阻止未完成的授权。取消会停止轮询子进程。

网络错误或授权检查失败不会放行工作台；可重试检查或重新授权。创建步骤逐项保存，丢失回执先从已有资源核对，不盲目重新创建。如果创建结果仍无法确认，保持阻塞并提示用户检查，避免重复资源。被用户移除的已登记资料不会静默补建。

运行中禁止更换授权账号；账号发生变化时需要完整退出并重新打开。已经准备好的不同账号资料各自保留，不回退到旧的共享演示账号。
