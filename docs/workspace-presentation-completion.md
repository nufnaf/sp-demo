# 工作台与桌面组件补齐

## 范围与实现

四个独立工作方向：招聘工作台、产品发布工作台、调研洞察、个人工作台。使用同一次 Electron 运行内的专属目录和工作台注册表；后面三个预置可打开的发布计划、访谈记录、本周重点，不预置本轮 JD 或真实任务完成记录。工作台切换关闭上个方向的业务窗口，任务、成果、洞察按 cwd 过滤，组件位置按工作台保存；刷新保留当前选择。

招聘开场按录屏恢复左侧业务目标、日程、最近成果，右侧当前任务与 AI 洞察。组件支持拖动；任务、真实文件成果、招聘洞察、会议从现有实际记录更新。业务目标为 6 位 AI Agent 工程师到岗，期限 10 月 31 日。面试通过不等于到岗，不把通过人数填入已到岗人数。日程明确显示会议实际日期。应用市场恢复 Dock 固定入口，使用现有应用目录、搜索和详情。

任务漏显根因：SDK 的 `SessionManager.listAll(customDir)` 只扫描指定目录的直接文件；旧代码传入 `presentation-runs/<run>/sessions`，而真实文件在 `sessions/recruiting`。运行中的临时记录短暂存在，空的磁盘结果与后续 idle 清理使任务消失；成果又依赖这些任务会话，因此一起漏显。修复为逐工作台目录调用 SDK，再合并。通过本机旧轮次真实文件验证，修复后能找回“查业务写 JD”，无须重新执行该旧任务。

当前任务保留已完成、执行失败、已停止及进行中状态；浏览器任务与其父任务合并显示，直接委派的招聘查询也出现在组件。文件成果继续来自成功 write/edit 的实际工具记录，不从回复文字伪造文件。

专用《星流科技业务介绍》修正三段业务介绍：星流科技提供企业 Agent 系统，不再把 Syntropic 写成其产品。飞书 CLI 使用已有资料维护身份完成精确段落修改并读回；只读应用的权限、凭据和 token 机制未变。工作目录提示明确 Syntropic 只是正在使用的办公工作台，JD 不应加入这个产品名称。

## 数据边界

新增方向在 `presentation-runs/<run>/workspaces/`，招聘目录继续 `workspace/`。四个方向新会话全部在本轮 `sessions/` 内，绝不回落写入原 Pi 历史。新建工作台也遵守该边界。正常退出先停止本 App 进程再清理整个本轮目录；下一次重新准备四个方向。原 Pi、模型配置和授权不清理。普通 Web 的注册表、会话浏览和持久化保留原路径。

会议仍只记录当前运行中的团队日程，不发送邀请。浏览器操作仍真实执行，浏览器固定 Luna；主模型后续按用户要求在 App 专属工作台默认改为 Luna（low），原 Pi 全局配置保留。预置资料与场景数据不冒充 Agent 本轮生成的结果。
